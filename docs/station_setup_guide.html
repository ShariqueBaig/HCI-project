Lab operations

Aura UI — Station Setup Guide

A 10–12 participant, 20–30 minute study on Windows lab PCs, with system audio as the intervention path.

Applies to build 2.0.0 · Windows 10/11 64-bit · Firebase project aura-ui-hci · collection aura_sessions

1. The one-page version

There are three moments, and only one of them is repeated:

MomentRuns onWhat it does
Once, for the whole lab any one machine Create lab_salt.txt, build AuraUI.exe, prepare one master folder, publish the Firestore rules.
Once per station each lab PC Copy the master folder, install Python + pycaw, run setup_station.ps1, confirm check passes. ~5 minutes per PC.
Once per participant the station they sit at prepare → participant works → verify → reset. ~1 minute of operator time.
The whole study in one command. Once Python is on a station, this does the per-station work end to end: 
powershell -ExecutionPolicy Bypass -File tools\setup_station.ps1 -SaltFrom \\labshare\lab_salt.txt -Code P01
Drop -SaltFrom if the salt is already beside the project, drop -Code to leave naming for later, add -Build to rebuild the exe.

2. What is identical everywhere, and what changes

The rule that keeps the dataset joinable: everything that identifies the participant is shared, everything that identifies the machine is automatic.

Same on every station
  • AuraUI.exe — byte-for-byte the same file; copy it, never rebuild per PC
  • lab_salt.txt — the same 64-character file; this is what makes P07 one person across machines
  • aura_defaults.json — public Firebase project id, Web API key, Spotify client id (compiled into the exe)
  • Firestore security rules and database
  • Consent text version (3.0) and the app build
  • Windows system volume as the audio path — no Spotify logins
  • No secrets.json needed; Aura Chat falls back to its built-in coach
Different per station
  • The folder path — anything writable, e.g. C:\AuraUI or the Desktop
  • The anonymous Firebase uid — created on first launch, stored in data\firebase_identity.json; never copy that file between PCs
  • Local sessions, journal.json, .cache — the station's own history
  • Participant code + condition — set per participant with prepare
  • Default output device and its volume level
  • Display / brightness behaviour (external monitors may not respond)
Never copy data\firebase_identity.json or settings.json from PC to PC. The first gives two machines the same anonymous identity; the second silently names a fresh machine after the previous participant. Copy the app folder before the first launch, or delete those two files after copying.

3. Once for the whole lab

3.1 Create the lab salt (one time, one machine)

python tools\lab_setup.py salt-init

This writes lab_salt.txt (64 hex characters) beside run.py. Every station must get this exact file. Copy it to a USB stick and to a shared network folder — \\labshare\lab_salt.txt is the example used throughout. It never leaves the lab and is never uploaded.

3.2 Build the exe once, then copy it

python -m PyInstaller --noconfirm --onefile --noconsole --name "AuraUI" ^
       --add-data "aura_defaults.json;." ^
       --hidden-import pycaw --hidden-import comtypes run.py

The two --hidden-import flags matter: the volume code imports pycaw lazily, so PyInstaller's static analysis does not see it. Omit them and the packaged app still runs — but silently falls back to the volume media keys, with ±2 % steps that some lab images block entirely. The result is dist\AuraUI.exe, about 24 MB, self-contained.

3.3 Prepare the master folder

Copy to a USB stick (or a share) so every station gets an identical start:

AuraUI\
  AuraUI.exe          <- the built exe
  lab_salt.txt        <- the shared salt
  docs\TESTER_NOTES.md

Keep a source checkout with tools\lab_setup.py on at least the operator's machine — prepare, verify, reset and check all live there.

3.4 Confirm the database is writable

Firestore must accept writes from anonymous users. The rules in docs/FIREBASE_SETUP.md allow create/delete only when the document's uid equals the caller's, and deny reads. If you skip this, every station will record locally and fail to upload. The per-station check (step 4.4) proves it in one line: write test: write + delete confirmed.

4. Once per station

4.1 Copy the folder to a writable place

Use C:\AuraUI (or the Desktop). Never C:\Program Files — the app writes settings.json, journal.json, .cache and data\ beside itself, and Windows blocks that.

4.2 Confirm the machine baseline

CheckExpected
Windows versionWindows 10 or 11, 64-bit
SoundA default output device exists (speakers or headphones); play something and confirm the tray volume slider moves it
InternetReaches firestore.googleapis.com; no captive portal, no proxy that strips TLS
Screen1366×768 or larger; the widget sits in a corner, keep it visible
User accountCan install Python and write to C:\AuraUI (no admin prompt needed for the app itself)

4.3 Run the station setup script

Best case: Python 3.9+ is already installed. If not, install it from python.org and tick Add python.exe to PATH. Then, from the project folder:

powershell -ExecutionPolicy Bypass -File tools\setup_station.ps1 -SaltFrom \\labshare\lab_salt.txt

Or double-click tools\setup_station.bat to get the same thing with the execution policy bypassed — lab images often block unsigned .ps1 files when double-clicked.

What the script does, in order:

  1. finds a Python (the py launcher first, Microsoft Store stubs skipped) and prints its version;
  2. creates .venv and installs requirements.txt — this is where pycaw comes from;
  3. copies the shared salt into place;
  4. runs lab_setup.py status, then the real check (name + Firestore write);
  5. optionally names the station (-Code P01) and rebuilds the exe (-Build).

Useful switches: -SkipDeps (no venv, no pip — fast re-runs), -SkipCheck (offline), -Condition control, -Force (prepare even with pending uploads). Exit code 0 means ready; 1 means read the [FAIL] lines. A lab script can gate on it.

Two things to fix before anyone sits down:

  • audio: Windows system volume via Core Audio — pycaw is present and volume is exact.
  • write test: write + delete confirmed — the station really reaches Firestore. Sign-in alone does not prove this.

If the audio line says volume keys, the exe was built without the hidden imports or pycaw is missing: run pip install pycaw in .venv, and rebuild with the flags in 3.2.

4.5 The GUI confirmation

Launch AuraUI.exe once and look at the Music panel. It should read System audio and Audio: Windows volume (Core Audio). Play a track, force a stress spike with the demo control, and watch the Windows tray volume slider drop and recover. That is the intervention working on the study's actual audio path.

Only one station needs -Build. Build on the operator's PC or the first station, then copy dist\AuraUI.exe everywhere. Building on 12 PCs takes 12× as long and risks 12 subtly different binaries.

5. Once per participant

WhenCommandWhy
Before they sit down python tools\lab_setup.py prepare --code P01 --condition intervention Writes consent, sets code + arm, clears the previous journal and Spotify login, checks Firestore, refuses if a session is still queued.
They work tick Record session, work 20–30 min, Journal → 0–10 ratings → Save entry Recording starts on the tick, and Save entry finalises + uploads the session.
After they leave python tools\lab_setup.py verify Shows each local session as uploaded / not uploaded and the queue length.
Before the next person python tools\lab_setup.py reset Clears the code, journal and Spotify cache; keeps the session archive.

Keep a paper sheet with the arm assignment: P01 intervention, P02 control, P03 control, … The arm is written into every uploaded document, so the sheet is only a cross-check — but a mis-typed --condition is not recoverable from the data alone.

5.1 A 20-minute participant, minute by minute

ClockOperator
−2 minverify on the previous participant, then prepare --code P0n --condition …. Read the pseudonym off the screen.
0Participant sits. Read the consent line, confirm they saw it. Launch the app.

+2 minverify → uploaded. Then reset. Station is ready for the next code.

6. Audio on lab machines

The intervention lowers the Windows master volume, so it works with Spotify, YouTube, a local file, or a phone over Bluetooth — the study does not depend on any music account.

Panel saysMeaningAction
Audio: Windows volume (Core Audio)pycaw is installed; exact 0–100 controlnothing
Audio: Windows volume (volume keys)no pycaw; media-key fallbackpip install pycaw, restart; rebuild exe with hidden imports
Audio: unavailableno default output devicefix the sound device in Windows settings
Audio: Spotifysomeone linked an accountfine, but not needed — reset forgets it

Do not link Spotify accounts for the study. The Development-Mode app allows 5 allowlisted users and the owner needs Premium; the sixth person gets “This Spotify account must be added as a test user.” Since system volume already delivers the intervention, linking only adds a failure mode. If a participant insists, add them under Dashboard → Settings → User Management before they sit down, and expect reset to log them out afterwards.

Auto-lowering ramps in small steps when the tier reaches Elevated and restores as the person calms. If the volume moves but nothing gets quieter, the sound is playing on a different output device than Windows' default — set the intended device as default.

7. Where the data goes

Firebase Cloud Firestore, in the project aura-ui-hci, collection aura_sessions, over the REST API with anonymous sign-in.

ItemValue
Project / collectionaura-ui-hci / aura_sessions
Document id<pseudonym>_<session_id>, e.g. e73582e4a42d3d2a_20261116-165231-6d9b6f
Authone anonymous uid per station, cached in data\firebase_identity.json
Consoleconsole.firebase.google.com/project/aura-ui-hci/firestore
Local copydata\sessions\<pseudonym>\*.jsonl beside the exe
Contentsnumeric telemetry (≤ 800 sampled ticks), summary, ratings, journal note + reflection, uid, chain_ok

One finished session is one document. Because every station shares the salt, the same participant code produces the same pseudonym everywhere, so their sessions join across machines and a withdrawal can delete all of them. Uploads are local-first: a failed write stays queued, retries every 5 minutes, and the .synced marker only appears after Firestore confirms.

9. Day-of checklist

  • Every station is a lab Windows PC and the app folder is writable
  • lab_salt.txt is byte-identical on every station
  • pycaw present — status shows system volume via Core Audio
  • status shows enabled, a station uid, pending: 0
  • Firestore rules published
  • check on every station: named + write test: write + delete confirmed
  • Consent text version matches the app (3.0)
  • Arm assignments written down (P01…P12 → intervention / control)
  • No Spotify logins needed; system audio is the path
  • prepare before each participant, verify + reset after
  • data\sessions backed up at the end of the day
  • Demo control tested once per station: tray volume drops and recovers
